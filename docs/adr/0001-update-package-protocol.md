# 更新包使用独立元数据消息 + 复用文件分片传输

更新互助需要一种"专门的更新分享语义"：接收端要在传输前就知道更新包的版本、大小与来源。决定在 core 协议中新增 `UpdatePackage` 元数据消息（版本号、文件名、大小、SHA256、来源设备），安装包本体仍复用现有 `FileChunk` 分片传输及其断点续传、SHA256 完整性校验链路。

- **Rejected**: 前端按文件名约定识别更新包——脆弱，不算专门语义，且无法在传输前携带版本信息。
- **Rejected**: 为更新包新建分片消息类型——与"文件分片统一走 FileChunk/Base64"的项目约束冲突，重复实现续传与校验。

接收端凭元数据在传输完成后校验 SHA256，并按版本号（仅当包版本高于当前版本）决定是否允许安装；安装为本地运行安装包，不依赖 GitHub。
